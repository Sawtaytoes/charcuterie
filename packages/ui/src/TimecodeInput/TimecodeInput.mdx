# TimecodeInput

A text field for a position in a piece of media — `hh:mm:ss.mmm` — with an `isRange` mode
for a section of a file. The consumer that shaped it is **QueuePilot**, which plays only a
chosen part of a video
([decision](../../../../docs/decisions/2026-09-01-a-timecode-is-milliseconds-and-a-section-is-a-mode.md)).

## The value is milliseconds, and the props say so

`onChange` reports an integer count of milliseconds from the start of the file. Not a
`Date`, not a clock time, not a string. A media position is a **duration**, the only
arithmetic anybody does with it is subtraction, and a number is the type that supports it.

Every prop carrying one keeps the `Ms` suffix — `durationMs`, `maxValueMs`, `minValueMs`,
`stepMs`, `valueMs` — because a duration's unit is genuinely ambiguous and this fleet has
both seconds and milliseconds in use. A `*At` timestamp is the opposite case and takes no
suffix.

```tsx
<TimecodeInput
  durationMs={file.durationMs}      // the default maximum
  label="Start at"
  onChange={(value) => { setStartMs(value) }}   // number | null
  valueMs={startMs}                 // seeds; Charcuterie owns it from then on
/>
```

## Why this is not `<input type="time">`

Two reasons, and neither is taste.

A `time` input's value is a wall-clock `HH:MM` string capped at 24 hours, its smallest step
is a second unless `step` is fractional, and it has no way to say "1.5 hours into a file" as
a duration rather than as half past one. A clip boundary is milliseconds; the platform
control cannot carry them.

And it is painted by the operating system, out of `::-webkit-datetime-edit-*`
pseudo-elements no token reaches inside — the same mechanism that deprecated the native
`Select` and that kept `Slider` off `<input type="range">`.

## Typing is the whole interface, so nothing guesses in silence

| Typed | Resolves to |
| --- | --- |
| `90` | `00:01:30.000` — a bare number is **seconds** |
| `1:30` | `00:01:30.000` |
| `90:00` | `01:30:00.000` — the largest field present is unbounded |
| `1:02:03` | `01:02:03.000` |
| `1:02:03.500`, `1:02:03,500` | `01:02:03.500` |
| `+90` | `00:01:30.000` — a leading `+` is tolerated |

Three mechanisms keep a grammar that permissive from being dangerous:

1. **The grammar is ordered and total.** Each rule is anchored on the *whole* input, the
   first match wins, and no match is a stated failure. `1:` is not one minute.
2. **An overflow is a failure with a name, not a carry.** `1:90` comes back as *A minute
   has 60 seconds, so "90" is not a seconds field. Type 02:30 to carry it, or 90 to mean 90
   seconds.* Both legal spellings are offered and neither is taken. Carrying it silently
   moves the position by a whole minute, which is the `1:60` trap mux-magic wrote down in
   2023.
3. **Nothing commits without an echo.** The resolved position is rendered in full underneath
   the field, in a `role="status"` live region wired into the input's `aria-describedby`.
   Commit is Enter or blur; a keystroke never commits.

The echo is a **reading of the focused field**, so it leaves when the focus does. A
restatement left under an idle control is an unlabelled timecode floating on the page, which
reads as a value rather than as a report on the one above it.

A **refusal** is the other case and it stays up, both kinds of it. The zero-length complaint
is written at the commit — which *is* the blur — so a rule that cleared it on blur would mean
it was never readable. And a text the grammar cannot read keeps `aria-invalid` on the
control, so the sentence saying why has to stay with it: an invalid field with no message is
worse than the stray line this removes. Emptying a live region announces nothing, so none of
this makes a screen reader chatty.

**The largest field present is unbounded; every smaller one is 0–59.** That one sentence is
every bound in the grammar. It is also why a bare number is seconds: seconds is the smallest
unit the field prints, so the reading that needs no explanation is the one where the typist
appended nothing.

**Milliseconds are optional to read as well as to type.** The grammar has always accepted
`1:01:00`, and the field now writes it back as `01:01:00` rather than as `01:01:00.000` — you
write 3, not 3.000. A real fraction still prints in full: `1:01:00.5` commits as
`01:01:00.500`, because a fraction pads on the right.

Refused by name: a negative, a seconds or minutes field of 60 or more with a larger field
beside it, more than three colon-separated parts, a fraction longer than three digits, and
anything the accepting rules do not match. A refused value leaves the text **exactly as
typed**, marks the field invalid and says why.

## A section is `isRange`, and both of its ends are optional

`{ end, start }` has four real states, not three plus an error:

| `start` | `end` | Means |
| --- | --- | --- |
| `null` | `null` | no window at all |
| set | `null` | from here to the end of the media |
| `null` | set | from the beginning, stopping here |
| set | set | the window between them |

So there is no `isEndOpen` prop — `null` already says it — and clearing one end never
touches the other. An open start is the **absence of a choice**, not zero, which is why a
half-open section is clamped but never compared.

Picking an end before the start **swaps**, following `DatePicker`: throwing the pair away
would discard the boundary just typed. An end **equal** to the start is **refused** by name,
which is where this parts company with a date range: a zero-length section plays nothing, so
swapping it would hide a typo behind a window that silently does not exist.

There is no `error` prop. `Field` and `FieldGroup` own the semantic error; this component
owns only the echo.

## Keyboard

| Key | Does |
| --- | --- |
| Enter | commits the typed text |
| Tab / blur | commits the typed text |
| Escape | puts the last committed value back |
| ArrowUp / ArrowDown | steps by `stepMs` (default 1000) and **commits** |
| Shift + ArrowUp / ArrowDown | steps by ten times `stepMs` |

A step commits, and that is not an exception to "a keystroke never commits" — it is the
other side of it. Typing is a draft the echo reports on; a step is a whole gesture on a
value that already exists, the same act as clicking a day in `DatePicker`'s calendar. A
stepper that needed Enter afterwards is a stepper nobody presses twice.

The control keeps the plain `textbox` role. It is **not** a `role="spinbutton"`: that role
promises an `aria-valuenow`, and this field has no value at all while it is empty or while
its text is refused — which are exactly the states the echo exists for. A spinbutton with no
value is a widget that under-reports itself to a screen reader in its two most important
states.

## The Narrow View stacks the two fields

A section is `[start] to [end]` in a row while there is room for it. Below `--cq-sm` the two
fields **stack**, and the `to` is replaced by a "Start" caption over the first and an "End"
caption over the second. Two `hh:mm:ss.mmm` fields and a word between them fill a 390px modal
edge to edge with no slack, which is where this was reported from.

It is a **container** query, not a window breakpoint. The box that ran out of room is this
field's own, and a 390px dialog on a 2560px monitor is the Wide View by every media query
ever written. The cost of `container-type: inline-size` is the `contain: inline-size` that
rides with it, so `TimecodeInput` takes its width from its parent rather than from its
content — give it a definite inline size, as with every container-query component here.

The captions are `aria-hidden`, exactly as the `to` always was. Each input already carries
`aria-label="<label> start"` / `"<label> end"`, and a real `<label>` would name the start
control a second time and fight the `id` a `Field` above clones onto it. **The accessible
name of each control is identical in both layouts**, and `TimecodeInput.test.tsx` asserts it
at two container widths.

## The formatter is exported, because the fleet writes it repeatedly

`formatTimecode`, `parseTimecodeInput` and `clampTimecode` come out of the barrel. The
printing half is written five times across the fleet — queuepilot's `clock` and `toClock`,
castkit's `formatTime`, and mux-magic's two modal formatters — each with its own answer to
whether the hour is shown and whether the minute is padded. A read-only surface should call
the exported one rather than spell a sixth.

```ts
formatTimecode(3_723_500)                                 // "01:02:03.500"
formatTimecode(90_000, { isHoursShown: false })           // "01:30.000"
formatTimecode(1_999, { millisecondDigits: 0 })           // "00:00:01" — truncates
formatTimecode(3_660_000, { millisecondDigits: "auto" })  // "01:01:00" — no fraction to print
formatTimecode(3_660_500, { millisecondDigits: "auto" })  // "01:01:00.500"
```

The **default is the canonical `hh:mm:ss.mmm`** and it stays that way, because a published
export is read by callers no change here can see. `TimecodeInput` opts in to `"auto"` for
both the text it writes back and its own echo, so the two agree on the page.

Either way it is one spelling per value: a re-read of the field parses to the number that
produced it, and a screenshot of the same value is the same picture.
