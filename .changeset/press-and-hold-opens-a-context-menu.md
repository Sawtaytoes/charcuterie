Add `useLongPress`, and give `Menu` an **anchor mode**, so a press-and-hold opens a context menu at the finger. The hook returns the handlers a pressable element spreads, fires once per press with the point in viewport coordinates, and cancels on a 10px drift so a scroll that starts on a card is a scroll. It arms for **touch and pen only** by default: a mouse already has a context menu, and the browser's own carries "Open link in new tab" and "Copy link address", which an app cannot reproduce. Two details in it are not obvious and both are measured in chromium — the native `contextmenu` is a **second trigger** rather than only something to suppress, because Chrome on Android recognises its own long press at about the same 500ms and fires `pointercancel` at the sequence, which would clear the timer a beat before it ran; and the click that ends a fired press is swallowed in the **capture** phase, because the handler that must not run is usually on a child, such as the anchor that fills a card. `Menu` takes `anchorRef` in place of `trigger`, and the two are mutually exclusive in the type. The anchor may be a real element or a **virtual** one — an object that knows only its own rectangle — so `flip` and `shift` work exactly as they do against a button and a press near the bottom of the window still gets a menu that fits. **`label` becomes required in anchor mode**, because with no trigger there is no `aria-labelledby` and the panel has no other name. The CSS half stays with the consumer: `-webkit-touch-callout: none` on the pressed element, or iOS draws its link preview over the menu.

`useAnchoredOverlay` re-reads `anchorRef` when the panel becomes visible, in a **layout** effect. Its comment already claimed the first half and the dependency array did not list `isVisible`, so the reference was read once on mount — invisible for a `Combobox`, whose input is mounted long before its panel opens, and fatal for a context menu, which aims its anchor milliseconds before showing. floating-ui with no reference positions at the viewport's top-left corner, which reads as a CSS bug rather than as a missing anchor.
