Without it `getByRole("status", { name: "Loading…" })` matches nothing — announced but unfindable, and axe is silent. `Badge` gets no role at all, for the mirror-image reason. |
| 2026-07-29 | [Ship no icons — and no symbol glyphs in a default](2026-07-29-ship-no-icons-and-no-symbol-glyphs.md) | **M3.** The plan's "own no icon set" extended one step: a component's own default may not be a symbol character either, because `⚙`/`↶`/`▨`/`⚠` render as *nothing* wherever the font lacks them — this sandbox's chromium, and the minimal kiosk and ePaper images. `MediaTile`'s fallback is the words "Image unavailable"; story boards use excluded-from-build story SVGs. |
| 2026-07-29 | [Five state kinds, not three](2026-07-29-five-state-kinds.md) | **M2.** Adds **RovingFocus** (focus is not selection — arrowing a listbox must not fire the form's `onChange`) and **Status**, a ~120-line typed FSM, to the talk's original three. Deliberately not XState, which owns state — the same conflict that rules out Radix for overlays. All member-having kinds store *intent* and derive the public answer from intent + who is mounted, which makes the invariants true by representation. `VisibilityControlProvider` → `VisibilityGroup`, answering v1's own `NOTES.md`. |
| 2026-07-29 | [Store injection, not a hard Jotai dependency](2026-07-29-store-injection-not-a-jotai-dependency.md) | **M2, and the one decision that could not be retrofitted.** Three members — `get`, `set`, `subscribe` — with a 20-line observable-ref default; `logic/jotai` and `logic/signals` are ~30-line optional adapters. Jotai's scoping is already paid for by context, and costs ~5–6 KB `slatecast` won't pay. The same model-based suite runs against all three stores, so proving an adapter costs one line. |
| 2026-07-29 | [The logic hooks are uncontrolled](2026-07-29-logic-hooks-are-uncontrolled.md) | **M2.** `isVisible` / `visibleKey` / `selectedValue(s)` / `activeValue` are **initial** values, read once. No controlled mode, no prop-sync effect — that is the thesis (Charcuterie owns the state), and v1's sync effects are exactly the echo loop the fleet already has. `onChange` fires on intent changes only, never on registration churn. |
| 2026-07-29 | [The container-query scale is `--cq-*`](2026-07-29-container-query-scale-is-cq-not-container.md) | **Kevin's call.** Tailwind v4 owns `--container-*` for its `max-w-*` scale at *different* sizes, so ours silently turned `max-w-md` into `max-w-lg`. Renamed rather than adopting Tailwind's values: nothing about a *visual direction* argues for changing what `max-w-md` means. Radius/tracking/font collisions stay — those carry a variant's character. Free exactly once, before publish. |
| 2026-07-29 | [The `is`/`has` rule has no external-API carve-out](2026-07-29-is-has-rule-has-no-external-api-carve-out.md) | **M2.** The carve-out is that `property` is not selected, so an *object-literal* key like floating-ui's `open:` never fires; a `typeProperty` is a shape we own and stays flagged. Foreign booleans we must *write* (React's `IS_REACT_ACT_ENVIRONMENT`) route through `Record<string, boolean>` rather than a declared type property. No `eslint-disable` — `reportUnusedDisableDirectives` is on. |
| 2026-07-29 | [Consumers link tokens by `portal:` until it publishes](2026-07-29-consumers-link-tokens-by-portal-until-publish.md) | A consumer branch proving the integration depends on the package by relative path and **stays unmerged** until npm publish. Copying the built CSS would prove the stylesheet looks right without proving the package *resolves* — which is exactly what broke during M1. Publishing first would put a version on the registry before any workflow existed to produce it. |
| 2026-07-29 | [The `v2` root is a Yarn 4 workspace; v1 parks in `packages/logic`](2026-07-29-v2-root-is-a-workspace-and-v1-parks-in-packages-logic.md) | v1's Yarn 3 PnP / rollup / jest / Storybook 7 tooling is deleted from `v2`; its 30 source files move intact to `packages/logic/src` with **no `package.json`**, so Yarn ignores them and nothing can depend on unported code. Excluded from Biome, ESLint, Vitest, and typecheck in one place each; M2 removes those as it ports. `master` still holds working v1. |
| 2026-07-29 | [Logical properties only, enforced on `className`](2026-07-29-logical-properties-only-enforced-on-classname.md) | `ps-`/`pe-`, `ms-`/`me-`, `start-`/`end-`, `text-start`/`text-end` — never `left`/`right`. Enforced by `no-restricted-syntax` from `@charcuterie/eslint-config`, scoped to `className` literals **and template chunks** and nothing else: matching `left`/`right` as property names would fire on `getBoundingClientRect().left`, and a rule that cries wolf gets switched off. The pattern's anchors keep `border-red-500` / `rounded-lg` / `place-items-center` clean. |
| 2026-07-29 | [`@charcuterie/tokens` is a separate zero-dependency package](2026-07-29-tokens-is-a-separate-zero-dependency-package.md) | Not a subpath of `ui`: `castkit/packages/views` needs values for Satori with no React tree, and `slatecast` has 60 KB gz. Different peer dependencies is the signal; tree-shaking is not the argument. React consumers still see one name via `@charcuterie/ui/tokens` — build-graph split, not API split. |
| 2026-07-29 | [**`daylight` is the default visual direction**](2026-07-29-daylight-is-the-default-visual-direction.md) | **M0 winner.** Light-first, cool neutrals, blue-violet accent, roomier rows, restrained motion. The other three stay as working `data-variant` alternates. Default *scheme* stays `dark`, so M1's "looks identical after the token swap" proof still means something. |
| 2026-07-29 | [ePaper removes animation, not just shortens it](2026-07-29-epaper-removes-animation-not-just-shortens-it.md) | Loop durations are tokens; ePaper and `prefers-reduced-motion` set `animation: none` rather than a `0ms` duration, because a zero-duration animation still holds keyframe zero — which for the indeterminate sweep is an empty bar, i.e. the exact "wedged drive" misreading it exists to avoid. Every moving affordance owes an opacity-free static fallback. |
| 2026-07-29 | [ePaper is a profile, not a scheme](2026-07-29-epaper-is-a-profile-not-a-scheme.md) | ePaper ships as `@charcuterie/tokens/epaper`, outside the three composing axes, because it *removes* capabilities (no hover, opacity, shadow, transition; six colours) rather than restyling them — and `data-scheme="epaper"` would wrongly imply a `data-variant` still applies. |
